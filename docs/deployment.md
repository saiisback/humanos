# Deployment and credential resume

No public deployment or Sepolia transaction has been performed without credentials. Local URLs are not public demo URLs.

The supported model configuration is `DEEPSEEK_API_KEY` and `JEV_API_KEY`, stored on the backend. Flue is the only agent framework. Do not place any model key in a `VITE_` variable or browser code.

1. Provision PostgreSQL17 and set `DATABASE_URL` in `.env` or hosting secret storage.
2. Create an app/relying party at https://developer.world.org. Set `WORLD_APP_ID`, `WORLD_RP_ID`, `WORLD_SIGNING_KEY`; select `WORLD_ENVIRONMENT=staging` only for the simulator, `production` for real proofs. Enable Proof of Human and the `humanos-root` action. Allow repeated verifications for this action. Root and approval proofs deliberately share this fixed action for same-human nullifier linkage; each approval has a new signed RP challenge and an exact canonical binding in its signal. Verify a real root/approval proof pair before claiming acceptance. Resume: `pnpm dev`.
3. Obtain DeepSeek and TypeSafe keys. Set `DEEPSEEK_API_KEY`, `JEV_API_KEY`. The source fixes `deepseek-flash` and `jev-1.13.0`. Run `pnpm --filter @humanos/models test`, then `pnpm dev`. Synthetic calibration is `pnpm calibrate`. After saving the key in `.env`, resume provider evaluation with `pnpm calibrate --live`; this small dataset does not establish production calibration.
4. Obtain an ENSv2 Sepolia parent name, RPC and funded operator wallet. Follow `packages/contracts` deployment instructions and supply verified registrar/parent values. Never use mainnet. Set `DEPLOYER_PRIVATE_KEY`, `SEPOLIA_RPC_URL`, and `HUMANOS_PARENT_LABEL`; run `pnpm --filter @humanos/contracts deploy:sepolia:dry`, inspect its output, then `pnpm --filter @humanos/contracts deploy:sepolia` and `pnpm --filter @humanos/contracts record:sepolia`. Set the resulting `ENS_REGISTRAR_ADDRESS`, owner `ENS_OPERATOR_PRIVATE_KEY`, and independent `ENS_AGENT_KEY_SEED` (0x-prefixed 32 random bytes). Set `ENS_AGENT_FUNDING_WEI` to enough testnet gas for an initial agent grant; each configured account/target is funded at most once through the journal, and later refills require explicit operator action; its default zero requires separately funding each derived account. The API wires both current authorization reads and finalized receipt publication.

For JAW passkey sign-in, set the documented public browser configuration `VITE_JAW_API_KEY` in the repository-root environment file and allowlist the exact `WEB_ORIGIN` browser domain in the JAW application settings. `VITE_JAW_APP_LOGO_URL` is optional and must be a public HTTPS image URL. The API requires backend-only `SEPOLIA_RPC_URL` to verify smart-account SIWE signatures; do not prefix this RPC or any server credential with `VITE_`. The web Vite config loads root environment files and exposes only `VITE_` variables in the browser build. Start the live journey with JAW sign-in, then complete Proof of Human to bind the human root. New ENSv2 roots record the bound JAW account as owner; registrar lifecycle roles remain separate.

5. Generate `FLUE_INTERNAL_SECRET` and `DEMO_SERVICE_SECRET` independently with `openssl rand -hex 32`. Set `API_URL`, `FLUE_URL`, `DEMO_SERVICE_URL` to internal service URLs; expose only the web frontend and authenticated API/Flue routes. Resume: `pnpm dev`.

6. Build with `pnpm build`; run the generated Flue server with persistent PostgreSQL and a single live owner per conversation. Use a single API writer for the MVP deployment. The PostgreSQL ENS journal coordinates nonces durably; every process using a signer must share this same journal. Never reuse the signer from an unjournaled script or clear pending rows. A stuck/dropped transaction requires reconciliation; the app deliberately does not auto-replace it with a fresh nonce. Back up journal rows with the application database. Deploy HTTPS reverse proxy with same-origin `/api` requests, set `WEB_ORIGIN` exactly, and put credentials only in server secret storage.

For the prepared Docker Compose setup, install Docker, set `POSTGRES_PASSWORD` and `WEB_ORIGIN=http://localhost:8080`, then run `docker compose up --build`. Docker was unavailable in the implementation environment, so this deployment configuration is not runtime-verified. Use URL-safe database passwords or percent-encode them in the connection URI. Public hosting requires a chosen host, DNS/TLS, and its deployment credentials.

Before public launch run every verification command in README, then perform and record the live World/ENS success, cancellation, expiry, revocation, and real Flue model recovery journeys. Event prize eligibility needs organizer confirmation for the direct official HITL protocol integration; no fixture proves eligibility.

Prepared task-local PostgreSQL can be resumed with:

```sh
/opt/homebrew/opt/postgresql@17/bin/pg_ctl -D /tmp/humanos-postgres -l /tmp/humanos-postgres.log -o '-p 55432 -h 127.0.0.1' start
pnpm dev
```
