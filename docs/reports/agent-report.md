# Task 9 — Flue durable HumanOS runtime

Implemented real Flue2.1 Node application in apps/agent. HumanOS uses `deepseek/deepseek-flash` with a custom Pi provider because Flue2.1's Pi0.83 dependency catalogs only the obsolete flash alias. Provider metadata and model name follow the official DeepSeek V4.1 release and current Pi catalog; production calls use https://api.deepseek.com and server-only DEEPSEEK_API_KEY. There is no fallback to retired model IDs. Only DeepSeek is bundled.

Every mounted /agents/humanos/\* surface (prompt, history, HEAD, abort, attachments) checks the current session cookie against API /api/internal/conversations/:missionId. Ownership service errors fail closed. Cross-origin POSTs are rejected; browser CORS permits WEB_ORIGIN with credentials. User prompts accept only kind:user/body:text, reject initialData and other fields, and cannot select another mission through tool arguments. The only tool is a zero-argument prepare_next_action bound to agent props.id and a fixed backend API_URL; it authenticates with FLUE_INTERNAL_SECRET. API independently rechecks current state, DeepSeek schema, Jev assessment and policy. No execution, shell or sandbox tools exist in this runtime.

useMission refreshes persisted business state before each accepted message; tools are offered only when mission state RUNNING, ENS identity present and expiry future. Mounted tools are affordances, not authority; the API rechecks before preparing actions, and the executor owns side effects. Ordinary tool retry semantics intentionally preserve unknown outcomes rather than blindly replaying effects; backend preparation is independently idempotent by mission/action type.

Source-root db.ts supplies @flue/postgres with a pg Pool driver and real transaction handling. Accepted prompts, conversation streams and Flue leases survive process lifetime. Business mission persistence remains separate. Durability is bounded to three attempts/five minutes. Deploy one live owner per conversation, per Flue's documented Node ownership constraint.

## Evidence and limitations

HTTP tests exercise anonymous access, all protected surfaces, cross-origin and initialData rejection, exact ownership URL/cookie forwarding, service failure, lifecycle-dependent tool availability, bound API tool routing and provider model ID. Real PostgreSQL tests use temporary schemas and verify accepted unfinished prompt survives pool closure, expired owner is requeued/reclaimed; a separate real Flue start/stop/start test proves a settled accepted receipt remains readable and the conversation can continue after restart. The latter uses Pi faux provider only in tests, not production.

This proves runtime/persistence mechanics, not live DeepSeek responses or a complete World/ENS mission. Live provider credentials were unavailable. Abrupt OS-process kill during a streaming provider response was not exercised; explicit persisted orphan-claim recovery and clean runtime restart were exercised.

Node22.12 needs --experimental-sqlite because Flue's Node entry imports node:sqlite even with PostgreSQL. Agent scripts include this flag. flue.config.mjs avoids Flue's native TypeScript-config requirement on Node22.12; Node22.18+ may use .ts directly. Production build binds HumanOS correctly; Rolldown emits a generic use-agent directive warning but generated \_\_flueBindAgentModule registration was inspected.

Final verification: 15 agent tests passed with Vitest4.1.11, package typecheck and ESLint passed, Vite8.3 production build passed. Built server was actually started on port3012 with real PostgreSQL: health returned200 and anonymous conversation returned401; process then stopped. Root pnpm test passed all then-current suites including 26 Foundry tests at 00:42 (agent14 at that snapshot); final added abort-data regression passed in isolated agent15 suite. Hono4.13.8/Valibot1.5 updates coordinated with lead.
