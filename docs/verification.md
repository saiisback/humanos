# Local verification — 25 September 2026

The JAW, Proof of Human, ENSv2 and chat implementation passes the local automated gates. These runs use synthetic JAW and World browser transports, fixture ENS/model/effect transports in the backend browser harness, real PostgreSQL, and real ENSv2 contracts on Anvil. They do not establish a live sponsor integration or public deployment.

Environment: Node 22.12.0, pnpm 10.12.4, PostgreSQL 17.11, Foundry 1.8.3, Chromium/Playwright 1.63.0. The browser suite covers JAW sign-in, rejection and backend verification rejection; logout/reconnect; a signed-in account without a human root; Proof of Human success, cancellation and unavailable paths; draft retention after session expiry; mission authorization and ENS identity; fresh sensitive approval; cancellation, expiry and revocation denials; application/calendar receipts, replay and reconciliation; JAW permission review, grant recording, rejection, revocation and unavailable transport; responsive geometry, keyboard sheets and Axe. `pnpm test:e2e` builds the current production web UI once before Playwright, then runs browser fixtures against an isolated Vite `e2e` mode at port 5183. Its synthetic adapters are absent from the production build. The backend-connected subset uses the real API, policy and PostgreSQL with external provider fixtures.

The mobile and desktop screenshots were inspected from unique Playwright output paths. At 320px, iPhone 13 size, 1280px, and a 640px CSS viewport representing 200% zoom, the page and conversation had no horizontal overflow, the composer remained visible, and the final transcript item could be reached. Each mobile sheet held keyboard focus, closed with Escape, returned focus to its trigger and produced no selected WCAG Axe violations.

Production authority remains server-side: SIWE is verified before a session is issued, PoH creates an account-bound root, ENSv2 authorization is rechecked for protected effects, and a browser JAW permission result alone does not activate onchain execution. The current onchain transfer executor is intentionally unavailable until a trusted independent permission verifier and effect transport are configured. Application and calendar rights are separate HumanOS/provider capabilities.

Live acceptance still requires JAW domain/account setup and a real SIWE round trip; a World app/RP with real Proof of Human and same-human action approval; funded ENSv2 Sepolia registration, role and receipt transactions; credentialed DeepSeek/Jev trials through Flue; and a public HTTPS deployment. Time to first live success remains unmeasured. The supported model variables are `DEEPSEEK_API_KEY` and `JEV_API_KEY` on the backend.
