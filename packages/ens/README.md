# HumanOS ENSv2 adapter

Backend-only Sepolia adapter composing the pinned official ENSv2 registry, resolver, EAC and HumanOSRegistrar interfaces. `createEnsAdapterFromEnv(process.env, journal)` constructs the writer and authorization reader; `createEnsPublicClient(loadEnsEnvConfig(process.env))` supplies a client for explicit pinned record reads.

Configuration requires SEPOLIA_RPC_URL and ENS_REGISTRAR_ADDRESS; writes require ENS_OPERATOR_PRIVATE_KEY and ENS_AGENT_KEY_SEED. ENS_AGENT_FUNDING_WEI optionally tops up each derived agent key for its own scoped status/receipt writes. Keys stay server-side. Deployment metadata lives under packages/contracts/deployments; a deployed HumanOSRegistrar must be configured separately.

Authorization intersects finalized and latest snapshots, official name resolution, controller records and actual argument-scoped EAC status/receipt grants. The latest head must be recent and must remain unchanged across reads. A moving head retries at most three times by default, then fails closed. Freshness defaults are 60 seconds maximum head age and 15 seconds future skew; configuration rejects nonfinite values and retry budgets outside 1–5. Revocations/narrowing seen at latest block grants immediately; new authority must also be finalized.

Registration retries require exact live identity/owner/capability/expiry matches; detached, expired or revoked hierarchy cannot be reused. The adapter explicitly reuses live roots at their actual expiry. All operator and agent writes use a durable PostgreSQL signed-transaction journal. API boot calls `initializeEnsTransactionJournal` and supplies `createPostgresTransactionJournal` from a separate connection pool, so held mission transactions cannot starve signer reservations. A transaction-scoped advisory lock and unique chain/signer/nonce constraint serialize signing across processes. Signed bytes and their hash commit before any broadcast; receipt timeouts and restarts only reconcile or resend those identical bytes. Initial agent funding uses a stable account/target intent, so a retry never replenishes spent funding. Reverted transactions are terminal. Every writer sharing a signer must use the same journal; never bypass pending entries, manually clear the journal, or send unrelated transactions with those keys. A missing journal or database fails closed. Arbitrary blockchain revocation and remote off-chain side effects cannot share an atomic transaction: execution must reauthorize immediately before its effect and use downstream idempotency.

Verification after independent review: 48 ENS tests pass, including real PostgreSQL restart/pending-transaction recovery and real Anvil deployment of pinned official contracts; coverage includes mid-read revocation, moving/stale/future heads, EAC-only grant removal, retry ownership/expiry mismatch, revoked/expired names, detached parent hierarchy, root-label/node mismatch, concurrent identical registration and funding/registration nonce serialization. No Sepolia broadcast or credentialed live execution is represented by these tests.
