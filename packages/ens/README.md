# HumanOS ENSv2 adapter

Backend-only Sepolia adapter composing the pinned official ENSv2 registry, resolver, EAC and HumanOSRegistrar interfaces. `createEnsAdapterFromEnv(process.env)` constructs the writer and authorization reader; `createEnsPublicClient(loadEnsEnvConfig(process.env))` supplies a client for explicit pinned record reads.

Configuration requires SEPOLIA_RPC_URL and ENS_REGISTRAR_ADDRESS; writes require ENS_OPERATOR_PRIVATE_KEY and ENS_AGENT_KEY_SEED. ENS_AGENT_FUNDING_WEI optionally tops up each derived agent key for its own scoped status/receipt writes. Keys stay server-side. Deployment metadata lives under packages/contracts/deployments; a deployed HumanOSRegistrar must be configured separately.

Authorization intersects finalized and latest snapshots, official name resolution, controller records and actual argument-scoped EAC status/receipt grants. The latest head must be recent and must remain unchanged across reads. A moving head retries at most three times by default, then fails closed. Freshness defaults are60 seconds maximum head age and15 seconds future skew; configuration rejects nonfinite values and retry budgets outside1–5. Revocations/narrowing seen at latest block grants immediately; new authority must also be finalized.

Registration retries require exact live identity/owner/capability/expiry matches; detached, expired or revoked hierarchy cannot be reused. The adapter explicitly reuses live roots at their actual expiry. Operator registration and funding share a per-account process lock including funding balance checks. One process must own an operator key; multi-process nonce coordination is not implemented. Arbitrary blockchain revocation and remote off-chain side effects cannot share an atomic transaction: execution must reauthorize immediately before its effect and use downstream idempotency.

Verification after independent review:41 tests passed including real Anvil deployment of pinned official contracts; coverage includes mid-read revocation, moving/stale/future heads, EAC-only grant removal, retry ownership/expiry mismatch, revoked/expired names, detached parent hierarchy, root-label/node mismatch, concurrent identical registration and funding/registration nonce serialization. No Sepolia broadcast or credentialed live execution is represented by these tests.
